# FocusKid — Project Vision & Architectural Invariants

## 1. Mission & Core Problem

**Місія** — надати дітям (5–13 років) автономний інструмент формування корисних звичок, який перетворює рутину на прозорий, самостійний процес без суперечок, а батькам — гарантію чесності виконання завдань через фізичну верифікацію результату.

**Проблема**:
- **Мікроменеджмент**: Батьки змушені контролювати кожну хвилину, що створює конфлікти.
- **Нечесність таймерів**: Стандартні таймери дозволяють дитині «обдурити» систему (скинути, перемотати, вимкнути).
- **Хмарна залежність**: Існуючі трекери вимагають інтернет, акаунти, підписки, показують рекламу — це небезпечно для дитини і не працює в поїздках/режимі польоту.

**Рішення (Цикл «Фокус ➔ Результат ➔ Підтвердження»)**:
1. **Вибір**: Дитина сама обирає завдання зі списку на сьогодні.
2. **Чесний таймер**: Запуск відліку без можливості примусового скорочення часу. Дозволена пауза (коротка) та додавання часу, але не «стоп» до закінчення.
3. **Реальний результат**: По завершенню таймер фіксує статус «Очікує перевірки». Дитина показує результат батькам.
4. **PIN-підтвердження**: Батьки вводять 4-значний PIN — завдання стає «зеленим» (успішним).

## 2. Architectural Paradigms & Technology Stack

- **Standard Mobile Stack**: **React Native with Expo (TypeScript)**.
  - Повна типізація TypeScript (`strict: true`).
  - Компоненти React Native з підтримкою доступності (TalkBack, WCAG AA).
  - Складання нативних Android артефактів через `npx expo prebuild` та Gradle wrapper (`./gradlew assembleDebug`).
- **Local-First / Zero-Network Persistence**:
  - Локальна реляційна база даних **`expo-sqlite`**.
  - Робота у 100% автономному режимі (Airplane mode, без інтернету, без хмарної синхронізації).
- **State-Machine Driven Timer**:
  - Таймер — це детермінований скінченний автомат (`Idle → Running → Paused → Completed → Verified`).
  - Переходи строго валідовані модульною бізнес-логікою.
- **Anti-Cheat Monotonic Time**:
  - Відлік через монотонний таймер (`performance.now()` у JS або нативний монотонний таймер), стійкий до ручного переведення користувачем годинника Android.
- **Secure Local Auth**:
  - PIN батьків хешується локально (PBKDF2/SHA-256 з локальною сіллю). Без відновлення через email чи сторонні сервіси.
- **Zero Binary Bloat in Git & GitHub Release Distribution**:
  - Бінарні файли `.apk` ніколи не комітяться у Git-гілки.
  - Зібрані Android APK завантажуються в **GitHub Releases** за допомогою `gh release create`, а пряме посилання публікується у коментарях до Pull Request.

## 3. Hard Invariants (Технічні вето)

- [INV-01] **Zero Network**: Заборонено додавати `android.permission.INTERNET` у production `AndroidManifest.xml` / `app.json`. Будь-яка спроба додати мережеву залежність (аналітика, телеметрія, зовнішні сервіси) блокується на етапі PR.
- [INV-02] **Monotonic Timer Integrity**: Заборонено використовувати системний час `Date.now()` для розрахунку тривалості сесії. Відлік часу тільки через монотонні годинники без стрибків назад.
- [INV-03] **No Early Termination by Child**: У стані `Running` дитина не може перевести таймер у `Completed` або `Verified` до спливу цільового часу.
- [INV-04] **Pause Abuse Protection**: Пауза має ліміт (макс. 5 хв на сесію або авто-резюме).
- [INV-05] **Parent Gate via PIN Only**: Перехід у батьківський режим (редагування завдань, перегляд статистики, верифікація) можливий тільки через валідний локальний PIN.
- [INV-06] **Verification Immutability**: Статус `Verified` (зелений) є фінальним і незмінним.
- [INV-07] **Local Data Persistence**: Усі дані зберігаються виключно в `expo-sqlite` на пристрої.
- [INV-08] **Landscape Parity**: Підтримка як портретного, так і альбомного (Desk Clock) режимів без розсинхронізації стану.
- [INV-09] **No Dark Patterns**: Жодних streak-штрафів, реклами чи пейволів.
- [INV-10] **Accessibility & Target Sizes**: Мін. розмір шрифту 48sp, сенсорні кнопки $\ge 48\times 48\text{dp}$, підтримка TalkBack.

## 4. Out of Scope (Non-Goals)

- Хмарна синхронізація, акаунти, бекапи в Google Drive.
- Віддалений моніторинг з телефону батьків.
- Вбудовані покупки, реклама, аналітика (Firebase/Sentry).
- Підтримка десктопних ОС (фокус: Android мобільні пристрої та планшети).

---

## 5. Target Constraints & Verification

- **Platform Target**: Android (API 24+ / Android 7.0+).
- **Fast Sandbox Verification**: Бізнес-логіка, модель даних та інтерфейсні компоненти перевіряються через `bun test` або `npm test` без потреби тримати активний важкий емулятор.
- **APK Verification**: Генерація APK через `npx expo prebuild` та `./gradlew assembleDebug` з публікацією у GitHub Releases через `gh release create`.
